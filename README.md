# Induction Mailer Workflow

The induction mailer now runs entirely from the console. It discovers the induction templates,
prompts for the intended recipients, and then either dispatches every email associated with a
stage or a specific template selected by number. Metadata is loaded from the header block of each
template so the same file describes the recipients, subject, attachments, delivery mode, and stage.

## Repository layout

- `InductionMailer.vbs` — console workflow that discovers templates under `templates/`, prompts
  for recipients and a stage/email choice, and prepares the personalised/broadcast deliveries.
- `templates/` — repository of HTML or text templates and their associated assets. Sub-folders are
  scanned automatically. Keep sibling `*.files/` folders (generated by Outlook) next to the template
  so inline images can be embedded automatically.
- `mail_utils_utf8_plus_dynamiclinks_ext/` — shared mail utility that sends messages and resolves
  the shared dynamic link placeholders.

## Template format

Templates start with a header block that is either wrapped by an HTML comment (`<!-- ... -->`) or the
legacy `@-- ... --` markers. Each line inside the block is a `Key: Value` pair; the keys are stored in
lower case inside the script. Example:

```text
<!--
To: person@example.com
Cc: another@example.com
Bcc:
Subject: Welcome to the group
Attachments: intro.pdf; .\checklist.xlsx
Stage: onboarding
Code: E1
Delivery: personal
-->
<html>...
```

- Leave a value blank (e.g. `Subject:`) to make the script ask for it when the template is used.
- `To`, `Cc`, and `Bcc` can be left blank if you want the script to rely entirely on the targets you
  enter at runtime. Supply multiple entries with commas or semicolons.
- `Subject`, `Attachments`, and any other key can be left blank. The script will prompt for missing
  values before dispatching the message.
- `Stage` is used when stage mode is selected. Supported stages are `onboarding`, `scheduling`,
  `authorisation`, and `finalisation`. The optional `Code` (e.g. `E4`) determines the ordering
  within a stage. The existing induction flow maps to `onboarding` for E1–E4, `scheduling` for
  E5–E6, `authorisation` for E7–E8, and `finalisation` for E9.
- `Delivery` must be either `broadcast` or `personal`.
- Any additional metadata keys you introduce become available as `[KEY]` placeholders inside the
  subject line, address headers, or body text.
- Attachments can be absolute paths (including UNC shares such as `\\server\share\file.pdf`) or
  relative to the template folder. Separate multiple entries with commas or semicolons. Relative
  paths starting with `./` or `.\` are resolved next to the template file.
- Use `[TOKEN]` placeholders consistently; the mailer scans the subject, `To`, `Cc`, `Bcc`, and
  body fields and only prompts for values that were declared in the header metadata (or that are
  well-known fields such as `NAME`/`SURNAME`). Placeholders with no corresponding metadata are
  left alone and noted in the log.
- The values supplied for `To`, `Cc`, `Subject`, and `Attachments` are injected into the Outlook mail
  alongside the runtime prompts and the recipients you provide when launching the script.

Placeholders such as `[NAME]`, `[SURNAME]`, or custom metadata keys are replaced automatically
wherever they appear in the subject line, `To`, `Cc`, `Bcc`, or body fields. The script gathers values
from header metadata, runtime prompts, and the shared link map; if a placeholder is unknown entirely
it is logged for review rather than prompting unexpectedly.

The `Delivery` tag determines whether the script sends a single broadcast (all targets in the `To`
line) or loops over each target to build fully personalised emails (with `NAME`, `SURNAME`, and
`FULL_NAME` populated per recipient).

Inline `<img>` references that point to a sibling `*.files/` folder (the structure Outlook creates
when saving a message) are rewritten to `cid:` URLs whether they use forward slashes or backslashes in
the saved HTML, so the graphics appear inside the email instead of as broken links.

## Dynamic link substitution

Hyperlink placeholders can be referenced as `[LINK_NAME]` (preferred) or with the legacy double
braces (for example `{{LINK_NAME}}`). The mailer loads `links_map.txt` into the placeholder context so
link tokens are resolved alongside other variables, and the Outlook utility still replaces any
remaining `{{...}}` entries before dispatch.

Keep the substitutions up to date by editing `links_map.txt` (either in the script directory or in
`mail_utils_utf8_plus_dynamiclinks_ext/`).

## Running the mailer

Run the script on Windows with Outlook installed:

```powershell
cscript //nologo InductionMailer.vbs [display|send|save]
```

The script then:

1. Prompts for a semicolon-separated list of target email addresses.
2. Asks whether to run in **stage** mode (send every template for the chosen stage) or **email**
   mode (send the selected template(s)).
3. Requests any metadata left blank in the template header, including the delivery mode if it was
   omitted.
4. For personal deliveries, looks up the recipient in the Outlook Global Address List (falling
   back to the Offline Global Address List and property accessors) to populate `[NAME]`,
   `[SURNAME]`, and `[FULL_NAME]`, prompting only if those lookups fail.
5. Builds either a broadcast message (all targets in one email) or one personalised email per
   recipient, attaches any referenced files, and opens/sends/saves it according to the command-line
   action (`display` by default).

Activity is logged to `InductionMailer.log` in the repository root. Your default Outlook signature
(including embedded graphics) is appended automatically.
